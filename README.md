# 현장노트 Voice · 자유발화 하자 기록

**소스코드 + 로컬 실행 도구 + 요구사항 + 다음 개발 계획**을 묶은 패키지입니다.
사용자가 확인한 `field_photo_voice_v2.html`에서 코드를 분리했습니다.
개발자 인수인계 패키지를 바탕으로 브라우저 한국어 음성인식과 자유발화 동·호수 추출을 연결했습니다.

> 핵심 목표: 세대에 들어가 점검을 시작한 뒤, **말하면서 촬영 버튼 한 번**만 반복한다.
> 사진마다 녹음 시작·종료·등록·업체 선택을 추가하지 않는다.

## 1. 실행

### Windows

Python 3.10 이상이 설치되어 있다면 ZIP 전체를 풀고 `start-local.bat`을 실행합니다.
터미널에서도 실행할 수 있습니다.

```powershell
py -3 scripts/serve.py
```

실행 후 브라우저가 열립니다. 주소는 `http://127.0.0.1:8080/index.html`입니다.
종료는 서버 터미널에서 `Ctrl+C`입니다. 포트 사용 중이면 `--port 8081`을 붙입니다.
Python이 없다면 Python 설치 후 실행하거나, 화면 확인용 단일 HTML부터 열어보세요.

### macOS / Linux

```sh
python3 scripts/serve.py
```

서버는 기본적으로 **해당 컴퓨터에서만 접근 가능한 127.0.0.1**에 바인딩합니다.
다른 휴대폰에서 접속하는 공개/사내 공유 서버가 아닙니다.
카메라·마이크의 실제 기기 시험은 별도의 HTTPS 개발 배포에서 확인해야 합니다.
현재 코드도 카메라 시작 전 보안 컨텍스트와 기기 API 존재 여부를 확인합니다.

### 설치 없이 화면만 보기

`dist/index.html`을 브라우저에서 열면 됩니다.
이 파일은 현재 `src`를 묶은 단일 HTML입니다. 로컬 파일 환경의 저장소·미디어 권한은
기기와 브라우저에서 별도 확인이 필요하므로 개발에는 위 로컬 서버를 사용하세요.

앱 자체에는 npm 설치, API 키, 외부 JS 라이브러리가 필요하지 않습니다.
Python 서버는 정적 파일만 제공하며 업무 데이터를 수신하거나 저장하지 않습니다.

## 2. 먼저 눌러볼 것

`내 등록 → 예시 36건으로 기능 체험`에서 목록을 채웁니다.
이어서 `사진 포함 엑셀`과 `집계·분석`을 확인합니다.
`현장 등록 → 화면 체험 → 점검 시작`에서는 촬영 버튼만 여러 번 눌러봅니다.
샘플 설명과 이미지는 실제 현장 자료가 아닙니다.

## 3. 파일 구성

```text
field-note-developer/
├── README.md                  이 안내
├── START_HERE.txt             메모장용 시작 안내
├── start-local.bat            Windows 실행
├── start-local.sh             macOS/Linux 실행
├── src/
│   ├── index.html             화면 구조
│   ├── css/styles.css         화면 디자인·모바일 반응형
│   └── js/
│       ├── core.js            저장소·촬영·연속 녹음·세션·백업
│       ├── speech.js          한국어 음성인식·자유발화 동호수 파싱
│       ├── xlsx-template.js   기존 엑셀 서식 템플릿
│       ├── records.js         분류·목록·선택·검색·상세 편집
│       ├── analytics.js       집계·반복 요약·예시 데이터
│       ├── excel.js           사진 포함 XLSX 생성
│       ├── backup-import.js   v1/v2 백업 가져오기
│       └── main.js            화면 이벤트·앱 초기화
├── types/current-data-model.d.ts  현재 저장 구조 참고용 타입
├── scripts/
│   ├── serve.py               로컬 개발 서버
│   └── build.py               수정한 src를 단일 HTML로 묶기
├── docs/
│   ├── REQUIREMENTS.md        사용자 요구사항·입력 최소화 원칙
│   ├── DEVELOPER_GUIDE.md     구조·저장 필드·함수별 수정 위치
│   ├── NEXT_STEPS.md          음성·클라우드·AI 다음 구현 범위
│   ├── TEST_REPORT.md         이번 패키지 검증 결과·미검증 범위
│   └── ORIGINAL_README.txt    기존 v2 안내 원문
├── tests/                    선택 설치형 자동 점검 코드
├── sample/photo-list-example.xlsx  기존 예시 36건 사진 엑셀
├── preview/                  기존 v2 화면 미리보기
├── original/                 사용자 확인 원본 HTML, 무수정
└── dist/                     src에서 빌드한 단일 HTML
```

**평소에는 `src`만 수정**하고, 수정 후 단일 파일이 필요하면 빌드합니다.
`original`은 비교/복구용이며 `dist`를 직접 수정하면 다음 빌드에 덮어써집니다.

```sh
python scripts/build.py
```

출력: `dist/index.html`
빌드에도 외부 패키지는 필요하지 않습니다. 원본 v2는 수정하지 않습니다.

## 4. 현재 기능과 연결 전 기능

| 구분 | 현재 상태 |
| --- | --- |
| 시작 → 연속 촬영 → 종료 화면 | 구현됨. 체험 문장으로 동작 확인 가능 |
| 실제 카메라·연속 녹음 | 코드 구현됨. 실제 휴대폰·장시간 현장 시험은 별도 필요 |
| 같은 동호수 유지 | 구현됨. 음성 또는 수동으로 바꿀 때까지 유지 |
| 위치를 음성으로 변경 | 구현됨. 문장 속 숫자·한글 수사 동호수 인식 |
| 실제 음성 → 텍스트 | 지원 브라우저의 한국어 Web Speech API로 구현 |
| 사진과 해당 설명 자동 연결 | 촬영 시 화면에 보이는 인식 문장을 사진에 저장. 최대 2.5초 지연 결과 보완 |
| 등록 조회·편집·삭제·검색·필터 | 구현됨 |
| 위치·공종·유형 분류 | 키워드 규칙. 사람이 수정 가능. AI 아님 |
| 사진 포함 엑셀 | 구현됨. 등록목록/집계 2개 시트 |
| 위치/공종/동호수/유형/일자 집계 | 구현됨. 실제와 체험을 분리 |
| 반복 지적 요약 | 동일 조합 3건 이상인 규칙 요약 |
| AI 하자 발생 가능성 예측 | 표시 시안뿐. 모델·확률 계산 없음 |
| 사이트/클라우드 업로드·동료 공유 | 미구현 |
| 사용자 로그인·현장별 권한 | 미구현 |

## 5. 기존 기록은 따로 옮겨야 합니다

**이 ZIP은 프로그램 코드입니다. 사용자의 브라우저에 저장된 사진/녹음/목록은 포함하지 않습니다.**

기존 v2에서 `기록 백업`으로 ZIP을 받고, 새 주소의 화면에서 `기록 가져오기`를 실행합니다.
같은 ID는 덮어쓰지 않는 가져오기입니다. 옮긴 후 사진·설명·녹음을 먼저 확인하세요.
호스트·포트·프로토콜 또는 브라우저를 바꾸면 별도 저장소가 될 수 있으므로,
기록이 보이지 않는다는 이유로 기존 데이터를 삭제하지 마세요.
코드 파일을 이메일로 전달하는 것만으로 기존 업무 기록까지 전달되지는 않습니다.

## 6. 개발 우선순위

먼저 `docs/REQUIREMENTS.md`로 입력 흐름을 확인한 다음 `docs/NEXT_STEPS.md`의
음성·사진 연결과 로컬 저장 안정성부터 구현합니다.
현재 음성인식은 Chrome/Edge 계열의 Web Speech API를 사용하며 네트워크와 브라우저 지원이 필요합니다.
CLOVA 전용 현장 용어 모델, 백엔드와 AI 연동은 별도 개발 범위입니다.

## 7. 자동 점검

일반 실행과 빌드에는 Python 표준 라이브러리만 사용합니다.
자동 UI 시험만 Playwright가 필요합니다.

```sh
python -m pip install -r tests/requirements.txt
python -m playwright install chromium
python tests/smoke_test.py
```

설치된 Chromium을 지정하려면 환경변수 `CHROMIUM_EXECUTABLE`에 실행파일 경로를 넣습니다.
결과는 `tests/output/`에 생성됩니다. 위 시험은 개발자 로컬 환경에서 네이티브
IndexedDB와 가상 미디어 장치를 확인하도록 작성한 코드입니다.
**이번 패키징 환경에서는 브라우저의 로컬 주소 탐색이 제한되어 전체 시험을 완료하지 못했습니다.**
대신 `python tests/ui_harness.py`로 메모리 저장소 기반 UI/엑셀/백업 로직을 확인했습니다.
테스트 전용 어댑터는 실제 앱과 빌드 파일에 들어 있지 않습니다.
가상/메모리 시험은 실제 휴대폰·영구 저장·현장 소음 검증을 대체하지 않습니다.
확인된 결과와 한계는 `docs/TEST_REPORT.md`를 보세요.

## 8. 전달 내용의 경계

패키징 기준일은 2026-10-16입니다. 소스 원본은 대화에 제공된 v2 파일입니다.
프런트엔드는 HTML/CSS/일반 JavaScript이며 React/Next.js/Flutter 프로젝트가 아닙니다.
브라우저 전역 변수를 공유하는 초기 구조를 유지했습니다. 보안 감사나 상용 운영 검증을
완료한 코드로 전달하는 것이 아니므로 실제 배포 전 권한·개인정보·보관 정책을 설계해야 합니다.
실제 API 키나 계정정보, 폰트 파일은 포함하지 않습니다.
